# Application: fs_demo

FsApi littlefs demo with remote file access over RPC.

Generated by `app_gen` from `common/templates/app`. The answers are recorded in
`.copier-answers.yml`; `app_gen update fs_demo` re-applies template
improvements on top of your local edits.

## Configuration

|             |                                                      |
|-------------|------------------------------------------------------|
| Networking  | `eth`                                                |
| Addressing  | `static` — 192.168.1.15/255.255.255.0 gw 192.168.1.1 |
| RPC server  | yes                                                  |

## Building

Boards are declared by the files in `boards/`. List them with:

```bash
make appboards
```

Build, flash and monitor:

```bash
make BOARD=<board> [PRISTINE=y] build
make flash
make mon
```

Boards need their fully qualified target on Zephyr 4.0, e.g.
`esp32s3_matrix/esp32s3/procpu`. `make help` lists every target.

## Networking

Wired ethernet via the board's MAC/PHY. The interface comes up through Zephyr's
connection manager; see `src/net_l4.c`.


The transport is declared **per board** in `boards/<board>.conf` as
`CONFIG_APP_NET_TYPE_<X>=y`, so one application can use different transports on
different boards. `common/scripts/cmake/app_net_type.cmake` reads that
declaration before Kconfig runs and asserts afterwards that the two agree.

## RPC

A ProtoRpc server listens on TCP port `CONFIG_TCPRPCSERVER_PORT` (default 13001)
with COBS framing. `SystemRpc` and `RtosUtils` callsets are registered in
`src/rpc.c`; add more there. `FsApiRpc` is registered as id 2 (see
[File system](#file-system)). Callsets are discovered by the host at runtime, so
there is no `callsets.yaml` to maintain.

```bash
systemrpc-cli --ip <device-ip> ...
rtosutils-cli --ip <device-ip> ...
fsapi-cli --ip <device-ip> ...
```

Build the host-side protobuf bindings with `make proto`.

## File system

The app is the test application for the `FsApi` module
(`common/modules/FsApi/README.md`). It does these steps:

1. `src/fs.c` calls `FsApi_init`. FsApi mounts littlefs at `/lfs`. The first
   mount formats the partition.
2. `src/fs.c` logs the volume statistics.
3. `src/fs.c` increments the counter in `/lfs/bootcount`.
4. `src/rpc.c` registers the `FsApiRpc` callset as id 2. A host can then read,
   write and format the file system with `fsapi-cli`
   (`python/fsapi/README.md`).

A file system error does not stop the app. The RPC server starts without the
file system.

### Flash layout

`boards/w55rp20_evb_pico.overlay` divides the 2 MiB flash:

| Partition        | Offset       | Size                     |
|------------------|--------------|--------------------------|
| `code_partition` | `0x100`      | to the fs partition      |
| `lfs_partition`  | top of flash | `APP_LFS_SIZE` (128 KiB) |

A code flash does not erase the fs partition. Files stay across flash and
reset operations.

To change the fs size for one build, set `APP_LFS_SIZE` in bytes. The value
must be a multiple of the 4 KiB erase block:

```bash
make BOARD=w55rp20_evb_pico PRISTINE=y build CMAKE_OPTS="-DDTS_EXTRA_CPPFLAGS=-DAPP_LFS_SIZE=0x40000"
```

A size change moves the partition. dtc then warns about the node unit address
(`unit_address_vs_reg`). The warning is harmless. If the code partition
becomes too small for the image, the link fails.

### Configuration

`conf/fs.conf` enables the file system:

| Symbol                          | Value | Reason                                     |
|---------------------------------|-------|--------------------------------------------|
| `CONFIG_FLASH`                  | y     | Flash access for the fs partition.         |
| `CONFIG_FLASH_MAP`              | y     | Flash access for the fs partition.         |
| `CONFIG_FILE_SYSTEM`            | y     | The Zephyr VFS.                            |
| `CONFIG_FILE_SYSTEM_LITTLEFS`   | y     | The littlefs file system.                  |
| `CONFIG_FILE_SYSTEM_MKFS`       | y     | `FsApi` depends on it, for `FsApi_format`. |
| `CONFIG_FS_LITTLEFS_CACHE_SIZE` | 256   | Must be >= `cache-size` in the fstab node. |
| `CONFIG_FSAPI`                  | y     | The FsApi module.                          |
| `CONFIG_FSAPIRPC`               | y     | The FsApiRpc callset.                      |

FsApi stops the build if `CONFIG_FS_LITTLEFS_CACHE_SIZE` is too small.
Without that check, the second open file fails with `-ENOMEM`.

### Console

The overlay moves the console and shell to UART0 (GP0/GP1). Connect the
Raspberry Pi Debug Probe UART:

| Probe U connector | Board          |
|-------------------|----------------|
| TX (orange)       | GP1 (UART0 RX) |
| RX (yellow)       | GP0 (UART0 TX) |
| GND (black)       | GND            |

Open the probe UART at 115200 baud, for example `/dev/ttyACM0`. The shell
answers there. Most boot log lines do not show on this console. Use
`fsapi-cli cat /lfs/bootcount` to see that the boot ran.

### Flash and test

```bash
make BOARD=w55rp20_evb_pico build
make BOARD=w55rp20_evb_pico flash
make BOARD=w55rp20_evb_pico reset
```

After `make flash`, run `make reset`. The flash runner does not reliably
start this chip.

From `python/.venv`:

```bash
fsapi-cli --ip 192.168.1.15 --refresh-bindings
fsapi-cli --ip 192.168.1.15 df
fsapi-cli --ip 192.168.1.15 tree /lfs
fsapi-cli --ip 192.168.1.15 put local.bin /lfs/local.bin
fsapi-cli --ip 192.168.1.15 get /lfs/local.bin copy.bin
fsapi-cli --ip 192.168.1.15 format
```

The `--refresh-bindings` step makes sure that the host knows callset id 2.

## LED

`src/led.h` exposes `app_led_init()`, `app_led_set()` and `app_led_toggle()`,
driving the devicetree `led0` alias the way `applications/blinky` does.

Boards that define `led0` in their own devicetree work as-is. For boards that do
not, `boards/<board>.overlay` supplies the alias; where the generator did not
know the pin it left a commented template there for you to fill in. Everything
degrades to a no-op plus one startup warning if no alias exists, so the app
still builds and runs.

## Layout

```
CMakeLists.txt   conditional sources and conf/ fragment selection
Kconfig          APP_NET_TYPE choice and app options
prj.conf         app-wide defaults
conf/            one fragment per concern; ip.conf owns addressing
boards/          one .conf + .overlay per supported board
src/             main.c plus one file per subsystem (see src/app.h)
```

`src/app.h` defines the init contract: every subsystem provides an
`app_*_init()`, and a no-op inline stands in when it is not built, so `main.c`
contains no preprocessor logic.
